# Policy: documentation

> Docs are part of done. Small, true, linked — and indexed so agents never read more than they need.

## Rules
1. **Owning doc per topic.** Goal → docs/GOAL.md; how we work → docs/OPERATING-MODEL.md; decisions → docs/decisions/NNNN-*.md (ADR); learnings → docs/operating-model/LEARNINGS.md. Link, don't duplicate.
2. **Update in the same change.** Behaviour, commands, structure or decision changed → doc updated in the same commit (`docs-sync` / `doc-keeper`).
3. **Index stays fresh.** `docs/INDEX.md` and `docs/knowledge-graph.json` are generated by `scripts/docs_index.py` (auto-run by a PostToolUse hook on markdown edits; checked in CI).
4. **Curated quick answers.** Recurring question → one row in the curated block of INDEX.md.
5. **Short files.** Prefer < 200 lines per doc; split by topic and let the index route. Start each doc with a one-line `>` summary — it becomes the index summary.
6. **Code knowledge graph.** For code structure, rely on codegraph (always current, local) rather than hand-written architecture prose; keep prose for *why*.
